# 精读：沿 Figure 1 理解 Rubric 方法地图

[阅读清单一：精读中提到的 70 篇论文](arxiv-2606.08625-references-mentioned.html) · [阅读清单二：其余 156 条参考文献](arxiv-2606.08625-references-remaining.html)

论文：[From Holistic Evaluation to Structured Criteria: Rubrics Across the Evolving LLM Landscape](https://arxiv.org/abs/2606.08625v2)，阅读版本为 2026-07-01 的 v2。以下页码均为该版本 PDF 页码。

本文重点解释各类方法的机制与区别。代表方法的介绍以这篇综述为依据，尚未逐篇复核全部原始论文；不把综述引用的结果当作统一条件下的横向实验。文中标为“阅读判断”或“说明性例子”的内容，是据此所作的分析。

## 1. 先读懂这张图：四块工作解决四个问题

![Figure 1：综述的整体组织框架](../assets/paper_images/arxiv-2606.08625-figure-1.png)

原文 Figure 1，第 5 页。中文图注：以 Rubric 的定义、分类和演进为基础，将构建与优化、评测、训练及可靠性组织为核心框架，并延伸到基准、应用和未来方向。

这张图最有用的部分是中间四块。它们回答的问题如下：

| 图中模块 | 它回答什么 | 最后产出什么 |
|---|---|---|
| 3 构建与优化 | 评价依据从哪里来，怎样修订？ | Rubric 条目、结构、权重或生成器 |
| 4 评测 | 怎样依据标准判断、解释和改进回答？ | 分项判断、证据、总分、修订反馈或候选选择 |
| 5 训练 | 怎样把这些判断转成可学习的信号？ | 奖励、偏好数据、训练样本或教师反馈，并据此更新模型 |
| 6 可靠性 | 标准和执行是否可信，在哪些条件下会失效？ | 质量诊断、执行检查、适用边界与防护措施 |

**阅读判断：这四块是观察方法的不同角度，同一篇论文可以占据多个位置。** 例如 TICK 既涉及从指令生成 checklist，也涉及用 checklist 改进回答；DR Tulu 既涉及训练，也涉及训练期间更新标准。把它们当成互斥类别，会丢失方法之间的联系。

图的上层回答“Rubric 有哪些形态”；下层说明“这些形态用在什么任务、还缺什么”。作者画出的历史阶段属于组织文献的视角，不宜理解为所有方法都必须依次走过的成熟路线。

## 2. 图的基础层：先把几个分类维度分开

来源：[§2](https://arxiv.org/html/2606.08625v2#S2)，第 6–10 页；Table 1 在第 7 页。

### 2.1 看什么、拆多细、依据什么，是三个不同问题

| 分类问题 | 选项 | 怎样理解 |
|---|---|---|
| 评价对象是什么？ | Output / Process | 看最终答案，或看推理、工具调用等中间过程 |
| 评价粒度多细？ | Holistic / Analytic / Atomic | 给整体判断；分维度判断；将单条标准变成尽量明确的二元命题 |
| 标准的依据是什么？ | Task / Behavior / Knowledge | 来自任务要求；来自实际回答与行为；来自外部知识和专业规范 |

“基于题目”不决定必须二元打分，“评价过程”也不决定必须采用某一种训练算法。一个过程级 Rubric 同样可以包含多个分级维度。

说明性例子：评价一份调研报告时，“必须包含三个方案”来自任务；“过去的回答经常把发布日期误当事件日期”来自行为观察；“某项事实是否符合原始公告”来自外部知识。三者可以出现在同一套标准中。

### 2.2 原子化的价值和代价

原子化让“这一项是否满足”更容易定位，也更方便复核。代价是：如果整体关系没有进入条目，逐条通过仍可能掩盖整体缺陷。

说明性例子：A 方案和 B 方案分别介绍正确，不能自动证明两者的成本比较采用同一口径。因此，“比较口径一致”需要单独检查，或保留整体验证。

综述 §4.1 同样提醒，分解是否有益取决于任务。阅读时应把“条目可独立判断”当作需要验证的设计目标，不能把它直接当作已经成立的事实。

## 3. 构建与优化：一套标准是怎样产生的？

来源：[§3](https://arxiv.org/html/2606.08625v2#S3)，第 12–16 页。

### 3.1 构建：差别主要在标准的来源

顶层分为专家编写、模型生成和人机协作。专家提供专业判断和隐含要求；模型提高生成规模；人机协作把人工放在提要求、修订、验证等关键位置。这些方式决定了谁提供评价依据，但都需要另外验证标准质量。

模型生成部分可以按以下机制理解：

| 路线 | 输入与核心动作 | 综述中的代表 | 主要需要检查的地方 |
|---|---|---|---|
| 从任务推导 | 从题目、指令或上层原则拆出要求 | TICK、RLCF、Qworld | 能否覆盖没有明说的要求；是否增加题目没有要求的限制 |
| 从回答差异归纳 | 对比优劣回答，提炼区分它们的规则 | OpenRubrics、CDRRM | 规则是否只解释这对回答；是否把长度、格式等偶然差异当成质量标准 |
| 从轨迹和错误归纳 | 从成功路径提炼关键步骤，或从失败路径提炼应避免的问题 | AutoRubric-R1V、DeepVerifier | 是否把某条可行路径误当成唯一正确路径；错误模式能否覆盖新情况 |
| 从知识迁移 | 将专业资料、网页、既有标准转成可判定条目 | LEGIT、RubricRAG、DR-rubric | 来源是否可靠、适用；条目能否追溯到依据 |
| 即时或按题生成 | 在当前输入到来时，生成适用的标准再判分或回答 | CARMO、Think-with-Rubrics、AdaRubric | 同题不同回答是否使用可比标准；生成成本与标准稳定性如何控制 |

**阅读判断：这个分类混合了“依据来源”和“生成时机”。** 按题即时生成，也可以使用回答对比或检索资料。实践中更适合同时记录“从哪里生成”和“什么时候生成”，而非强行只归入一类。

以 OpenRubrics 为例，这篇综述关注它从偏好回答对中提炼标准的作用。仅根据这一描述，不能进一步推断它在线交替训练生成器、Judge 和回答模型；具体训练机制仍需读原论文。

### 3.2 优化：反馈到底改了什么？

作者区分外部信号驱动的修订与更主动的演化。理解具体方法时，最有用的是定位反馈和更新对象：

| 修订路径 | 反馈来自哪里 | 被更新的对象 | 代表与机制 |
|---|---|---|---|
| 按评分错误修补 | 人机分歧、错误类型、专家批注 | 条目文本、覆盖范围、粒度 | Reflect-and-Revise 围绕评分不一致修订；Feedback-to-Rubrics 利用预测与专家批注的差距发现遗漏 |
| 学习更有区分力的标准 | 偏好对、下游表现或可预测的质量信号 | 标准生成过程或生成器 | SVR 从偏好对挖掘区分特征；OptimSyn 使用合成样本对模型改进的贡献作为反馈 |
| 根据当前模型更新 | 新回答差异、新错误或已饱和条目 | 当前使用的标准集合 | OnlineRubrics 比较当前与参考策略的回答；DR Tulu 更新正向要求和防止投机的负向规则 |
| 让模型组件共同学习 | 一个组件改善另一个组件的任务表现 | 生成器、Judge 或策略参数 | EvoLM、Rubric-ARM 等；具体更新关系见后文 |
| 保留长期诊断信息 | 多轮训练的失误与区分能力变化 | 记忆库和后续标准 | AMARIS、SibylSense 保留历史信息，追踪反复失败或已经饱和的要求 |

**阅读判断：动态与训练是两条轴。** 每题重新生成一份 Rubric，可能全程使用冻结模型；训练一个生成器，也可能只训练一次、部署后保持不变。“标准变了”和“参数更新了”应分别说明。

## 4. 评测：标准生成后，怎样真正用起来？

来源：[§4](https://arxiv.org/html/2606.08625v2#S4)，第 16–20 页。

### 4.1 把总分拆开：拆维度与改量尺是两件事

结构分解决定评什么：例如分别看事实、覆盖和逻辑。量尺设计决定每项怎样表达结果：分级分数、二元判断，或加分项与扣分项。

LLM-RUBRIC 的特色是用分维度判断及校准网络刻画评价者差异；HealthBench 使用专家编写的二元条目；SedarEval 将应得分的内容和应扣分的错误分开。这些设计的共同收益是能定位差异，但不保证不同设计之间的总分天然可比。

说明性例子：“没有提到一个优点”和“声称了一个错误事实”可以具有不同的评分后果。将两者写成独立的覆盖项和错误项，比让 Judge 凭总体印象决定更容易复核。如何加权、是否存在否决项，则仍是额外的设计选择。

### 4.2 忠实执行：给判断加证据，再检查非语义变化

| 方法方向 | 要解决的问题 | 代表机制 |
|---|---|---|
| 标准固定与证据约束 | 同一次比较中标准漂移；评分无法复核 | RULERS 将标准固定为版本化集合，并要求评分引用可审计证据 |
| 分开评估不同目标 | 不同维度互相干扰 | DeCE 将精确性与召回式检查分开执行 |
| 条目级验证 | 总分对了，但分项可能判错 | RubricEval 直接检查单项标准执行是否正确 |
| 降低提示结构偏差 | 顺序、分值标识、示例影响判断 | 调整或锁定评测设计；FairJudge 通过训练降低对非语义变化的敏感性 |
| 校准边界与处理不确定性 | 邻近等级难区分，低置信判断不稳定 | 使用评分边界样例，或通过共识与转交复核处理不确定情况 |

这部分与 §6 的执行可靠性相呼应：§4 主要列出怎么做，§6 进一步追问这些做法仍留下哪些问题。

### 4.3 超出打分：评测结果还能改回答和选路径

一种方式是“生成回答 → 逐项检查 → 按反馈修改”。TICK 是代表；iRULER 进一步给出满足原因、未满足原因和改进方向。Think-with-Rubrics 则把标准放进回答之前，让生成过程先有质量要求。

另一种方式是先生成多个候选，再使用 Rubric 排序或筛选。它把计算量花在候选探索与验证上。两种方式都可以发生在推理阶段，无须在本次任务中更新模型参数。

**阅读判断：这类方法至少有两个需要分别测量的结果。** 一是评分与人是否一致，二是被它修订或选中的回答是否真的更好。只证明前者，尚不足以证明整个回答改进流程有效。

## 5. 训练：Rubric 怎样进入模型更新？

来源：[§5](https://arxiv.org/html/2606.08625v2#S5)，第 20–28 页。

### 5.1 先看奖励落在哪里

| 信号位置 | 具体机制 | 代表 | 与上一层相比改变了什么 |
|---|---|---|---|
| 完整回答 | 对多个条目评分，按规则组合奖励 | RaR、RLCF、RBR | 能看到回答在哪些要求上成功或失败 |
| 混合验证 | 可执行的条目用确定性验证器，其余交给 Judge | RLR3 | 不同条目使用不同证据和验证方式 |
| 推理步骤 | 将条目对应到满足或违反它的步骤 | SRaR、AutoRubric-R1V | 反馈开始定位到过程中的具体位置 |
| token | 识别与某项要求相关的 token，再分配训练信号 | RTT | 避免把局部要求的奖励平均分到整段内容 |
| Agent 轨迹 | 用行为特征刻画长程交互，并结合最终任务结果 | Critic Rubrics、SWE-TRACE | 将最终成败与中间行为联系起来 |

**阅读判断：多个分项分数不自动等于更细的训练归因。** 如果最后仍然合成一个回答级奖励并用于整个回答，诊断信息虽然更丰富，学习信号却未必精确落到造成问题的步骤。SRaR、RTT 之所以值得单列，正因为它们进一步处理了“奖励应该归给哪里”。

同样，图中画出奖励向量，不代表所有 Rubric RL 方法都把完整向量直接送进优化器。需要继续查看聚合、归一化和 advantage 的计算。PAPO 就专门讨论多维信号如何分别归一化再聚合，以改善训练稳定性。

### 5.2 在线训练：回答在变化，奖励也可能需要适应

在线 RL 的共同骨架是：策略生成当前回答，验证器或 Judge 根据标准给出信号，训练过程据此更新策略。Rubric 扩展了能提供反馈的任务范围，但每种工作解决的瓶颈不同。

| 瓶颈 | 方法如何处理 | 代表 |
|---|---|---|
| 没有唯一标准答案 | 将质量要求拆成可以分别检查的条目 | RaR 从参考答案构造要求；RLCF 从指令构造要求；QuRL 借助检索资料 |
| 模型难以探索出好答案 | 在采样或修订时提供标准引导 | RGR-GRPO 利用标准指导轨迹修订；RuscaRL 逐渐减少对外部标准提示的依赖 |
| 回答级奖励过粗 | 把信号分配到步骤或 token | SRaR、RTT |
| 学会利用 Judge 漏洞 | 加强验证器、更新负向规则或引入执行结果 | AdvancedIF、DR Tulu、StitchCUDA |
| 长任务难以分配责任 | 按阶段、行为或证据组织反馈 | Critic Rubrics、CaRR 等 |
| 模态不同 | 组合共用要求与模态专属要求 | Omni-RRM；视觉任务还有实例相关的空间、属性等条目 |

这些路线可组合使用。使用 Rubric 作为奖励来源，并没有预先规定标准必须动态更新，也没有规定 Judge 必须和策略一起训练。

### 5.3 离线使用：标准通过数据间接影响学习

第一条路径是偏好数据。Rubric 可以帮助筛选偏好对、判断优劣，或控制合成回答满足哪些要求；之后由 DPO 等方法学习这些偏好。rDPO 与 CPT 在综述中分别代表筛选和可控合成。

第二条路径是监督训练。先生成多条轨迹，按行为标准选出较好的轨迹，再用其训练模型。它与只看最终是否成功的筛选区别在于：同样成功的轨迹仍可能具有不同的行为质量。

还有一类是 Rubric 引导的蒸馏：标准让教师明确指出学生欠缺哪些能力，或者让教师在标准条件下提供更细的学习信号。综述将 ROPD、RGSD、RCSD 放入相关讨论。

**分类核对：§5.4.2 标题是监督微调，但其中对 ROPD 的描述包含学生 rollouts 上的 policy-gradient 更新。** 因此，该节更适合作为“Rubric 参与数据选择和蒸馏”的阅读入口；不能仅根据章节名把列出的工作都认定为固定数据上的普通 SFT。实施前要回到原论文确认采样方式、损失和更新对象。

### 5.4 标准与模型共同变化：分清谁和谁在学习

| 组织方式 | 更新关系 | 代表 | 阅读时必须继续确认 |
|---|---|---|---|
| 共享参数 | 一个模型承担多个角色，共同训练相关能力 | EvoLM | 共享的是 Rubric 生成、回答生成还是评分角色；每个角色分别用什么目标 |
| 分组件交替更新 | 固定一个组件，训练另一个组件，再交换 | Rubric-ARM、RUBRIC-ARROW | 每阶段固定谁、更新谁；偏好标签从哪里来 |
| 对抗改进 | 评价方寻找薄弱点，回答方学习修正 | RLAC | 外部验证器如何确认缺陷，避免纯粹互相迎合 |
| 持续修订标准 | 按当前能力与历史错误调整条目 | OnlineRubrics、DR Tulu、AMARIS | 条目变化是否也伴随参数训练；保留什么稳定的评估参照 |

以综述对 Rubric-ARM 的描述为例：固定生成器时训练 Judge，使其更符合偏好；固定 Judge 时训练生成器，使产生的标准更有助于区分回答。这个循环的直接对象是生成器与 Judge，不能凭“共同演化”再加上一个未经确认的回答模型更新步骤。

**阅读判断：三个词需要分别验证——会生成标准、会执行标准、没有标准提示也会按这些要求回答。** 前两种能力的提升并不能单独证明第三种能力已内化。论文 §8.4 本身也将这种持续内化视为开放问题。

## 6. 可靠性：把失败定位到正确的一层

来源：[§6](https://arxiv.org/html/2606.08625v2#S6)，第 29–32 页。

| 层次 | 典型失败 | 怎样区分 | 文中相关工作 |
|---|---|---|---|
| 标准质量 | 漏掉核心要求、增加无关要求、条目歧义或重复 | 固定执行条件，比较标准；让专家直接审查条目 | RubricBench、RIFT |
| 执行忠实度 | 标准没问题，Judge 却漏看证据或受措辞影响 | 固定标准，对照条目级判断；做保持语义的顺序或措辞变化 | RubricEval、Sage、评分偏差研究 |
| 目标与表达边界 | 条目全满足但仍不够好；高分区挤在一起；分数不预测真实效果 | 检验高质量候选的区分力、整体评价和下游目标 | CARMO、Tournament-GRPO、criterion validity 研究 |
| 安全威胁 | 有意修改标准或利用 Judge 弱点，引导错误偏好 | 检查目标子集和训练后行为，不能只看总体分 | RIPD、CHERRL |

阅读判断：人机总分不一致只是排查入口。至少应对齐题意、reference、人评依据、Rubric 和 Judge 理由，才能判断问题发生在哪一层。仅根据一个分数差直接改标准，可能把执行错误写进规则。

### 6.1 对综述中的强结论，需要保留适用范围

第一，有限固定标准无法覆盖所有可能目标，并不推出“每个固定任务上的固定标准都无效”。该结论也不能单独证明某个动态生成器有效；动态标准仍需要正确性、稳定性和泛化证据。

第二，Rubric 可以产生结构化反馈，但最终仍可能通过标量奖励更新策略。综述 §5.1 对标量奖励的批评和 Figure 8 的对照表达较强，阅读时应分别核对反馈内容、聚合方式与优化目标。

第三，§6.5 对多解任务中标准缺少锚点的表述比较宽。阅读判断是：多解任务仍可能存在共同约束；更具体的困难在于，有些质量差异难以通过独立条目充分表达。作者也讨论了保留结构、改用动态证据判断的混合路线。

第四，自我生成、自我评价和自我训练可能共享盲点。减少人工标注不意味着无需外部依据：§8.1 明确讨论了独立质量参照的重要性。

## 7. 图的下层：基准和未来方向怎样接回方法？

来源：[§7–8](https://arxiv.org/html/2606.08625v2#S7)，第 33–39 页。

Table 2 的作用是展示任务差异：通用基准关注指令与标准本身，专业基准强调领域知识，深度研究关注长报告和隐含要求，多模态任务需要感知层面的标准，学术任务涉及复现、评审和表达。各表项的“数据规模”不能直接相加或当成同一种样本数，有的对应任务，有的对应 Rubric 条目。

这里有一处值得注意的内部不一致：§7 的总结称专业类别中每个基准都采用专家构建，但 Table 2 同时列出 XpertBench、LP-Eval 和 PanCanBench 等人机协作条目。稳妥的归纳是“专业领域强调专家参与”，不宜照搬“全部由专家独立构建”。

未来方向可以与前面四块直接对应：

| 开放方向 | 前面留下的问题 |
|---|---|
| 可靠生成 | 谁来证明生成的标准合理，尤其在生成与评价使用相同模型时？ |
| 动态标准 | 如何改善区分力，同时保持不同模型、不同时间之间的可比性？ |
| 多模态统一 | 哪些质量原则可以共用，哪些必须按视觉、语音等分别定义？ |
| 标准内化 | 移除外部提示后，能力能否持续；模型能否自行发现并纠正错误？ |

动态标准的一个关键张力是：标准与模型同时变化时，分数上涨可能混合了能力变化与标准变化。论文讨论稳定的高层维度与动态的实例条目相结合，但如何验证这种分层仍是研究问题。

## 8. 用一个例子把四块连起来

以下为说明性例子，不是论文中的实验。

假设任务是“根据给定资料，比较三个方案并提出推荐”。

**构建：**从题目提取“三个方案都覆盖”；从资料提取“成本数值可追溯”；从历史错误补充“不得混用不同年份价格”；再加上“推荐理由必须对应前面的比较”。

**评测：**逐项查证并记录证据。若某条没有通过，先判断是答案缺陷、标准不适用，还是 Judge 读错。修复答案后重新评分，属于推理时改进，参数可以完全不变。

**训练：**收集多个回答，可以用分项分数构造奖励进行 RL，也可以形成偏好对进行 DPO，或挑出好样本进行 SFT。这三条路径消费的是不同形式的监督信息。

**优化标准与验证：**若模型都能完成覆盖项，却仍在方案权衡上差异明显，就需要检查现有标准是否饱和。新增标准后，应在独立回答上验证它是否提高真正的区分能力，并保留稳定的评估参照，避免仅凭训练中使用的新总分判断进步。

这段流程中的每个箭头都可以单独研究。读一篇具体论文时，先定位它到底改变了哪一个箭头，比只看它是否使用“Rubric”更容易理解贡献。

## 9. 后续读原始方法时，固定追问五件事

以下是依据综述整理的阅读框架。

| 要追问什么 | 为什么影响方法判断 |
|---|---|
| 生成标准时看到了什么？ | 只看题目、看 reference、看带标签的回答对，是不同的信息条件 |
| 谁提供正确性的参照？ | 人评、执行结果、教师判断和自身评分的证据强度不同 |
| 哪些东西在更新？ | 条目文本、权重、生成器、Judge 和回答模型不能混为一谈 |
| 反馈怎样进入训练？ | 选数据、构造偏好、生成标量奖励、分配步骤信号，对应不同机制 |
| 怎样证明改善来自标准？ | 需要控制 Judge、数据量和回答集合，并检查未参与修订的样本 |

对这篇综述的整体评价：它适合提供方法入口和研究问题，尤其帮助分开“生成标准、执行标准、用标准训练、验证标准”四件事。具体实现仍需沿这五个问题回到原论文；章节归类与示意图不能替代训练细节。
