# ARCO：监督信号与逐题训练示例

来源：[论文 v2](https://arxiv.org/abs/2606.21262v2)，2026-07-23 更新。本文依据已审核草稿 v2 入库。

先用教师生成的逐步 Rubric 和分数训练评价模型，再用最终答案对错约束各步分数之和，与 Agent 一起持续训练。后续评分损失通过共享参数间接影响 Rubric 生成，没有逐条修订标准的直接监督。

## 研究动机

多步 Agent 只获得最终成功或失败的奖励时，很难判断哪次搜索有效、哪一步导致失败。逐步 Rubric 可以把评价依据写出来，让奖励具有可读的解释。

同时，Agent 在训练中遇到的错误会变化：早期可能搜错人物，后期可能重复搜索或过早回答。作者希望评价模型持续学习当前 Agent 的行为，使奖励能够跟上这些变化。

## 解决问题

研究如何将最终答案的正误信号转化为逐步奖励，并让生成标准、预测分数的模型持续更新。

这里有两个需要区分的目标：一是学会生成与当前动作有关的评价标准；二是学会把最终结果分配到各个步骤。ARCO 在预热阶段为两者提供教师监督，后续主要利用最终结果训练评分，再通过共享参数影响标准生成。

## 现象分析

论文中的“协同进化”需要理解为模型参数持续更新。它没有显式地找出旧 Rubric 的缺陷、提出修改，再验证修改版是否更好的流程。

实验表明，生成的标准具有一定动作针对性：独立 Judge 根据 Rubric 从四个动作中识别对应动作，准确率为 42.46%–54.80%，高于随机水平 25%。但识别对应动作与标准正确、完整、符合人评，是不同的验证问题。

附录还揭示了奖励分配的不足：Finish 步骤分数区分最终成功与失败的 AUROC 为 0.816–0.873，中间 Search 步骤只有 0.583–0.650。奖励的区分力更集中在最终回答上。

## 主要方法

Rubric 模型输入问题、已有交互轨迹和当前动作，用共享骨干的生成头写出三条标准，评分头结合上下文和标准预测逐条分数，取等权平均作为步骤奖励。条目数量和平均规则是固定设置，模型参数参与学习。

预热时，教师阅读完整轨迹，提供标准文字和逐条分数。模型通过文本交叉熵学习教师标准，通过平方误差拟合校正后的教师分数。后续训练不再持续获取教师标注，只用最终答案的正误，要求各步分数之和接近正确时的 1 或错误时的 0，并以 KL 约束限制偏离预热模型。

评分损失更新评分头和共享骨干，间接改变以后生成标准的概率；梯度不穿过已经采样的标准文字。因此，后续没有“这一条标准该怎样修改”的直接监督，也不能仅凭总分正确保证逐步评分合理。

## 用一道题说明监督信号

以下题目、标准和数字均为解释机制的示意，不是论文实验案例。

题目：**“张三任教的大学成立于哪一年？”**

数据集标准答案：**1902 年**。

预热数据中有一条解题过程：

- 第一步：搜索张三任教的大学，找到 A 大学。
- 第二步：搜索 A 大学成立年份，找到 1902 年。
- 第三步：提交答案：1902 年。

教师阅读完整过程，为各步写标准并评分。例如第一步：

| 教师提供的 Rubric | 教师原始分数 |
|---|---:|
| 搜索的人物是否正确 | 0.9 |
| 是否找到任教关系的证据 | 0.8 |
| 是否避免无关搜索 | 0.7 |

**预热的监督信号就是这些标准文字和分数。** 分数还会经过校正，使各步平均分之和与最终正误一致，模型实际拟合的是校正后的标签。

对第一步进行训练时，生成头学习输出教师标准；评分头读取上下文、动作和标准，学习预测目标分数。文字预测与教师文字的差异产生文本损失，分数预测与标签的差异产生评分损失。教师标注属于模型生成的监督数据，不能直接视为经过人评验证的金标准。

进入后续训练，Rubric 模型自己生成标准、预测分数。假设新轨迹得到：

| 步骤 | 模型预测的步骤平均分 |
|---|---:|
| 找到大学 | 0.1 |
| 找到成立年份 | 0.2 |
| 提交最终答案 | 0.1 |
| **总和** | **0.4** |

最终答案与数据集标准答案一致，所以监督标签为 **R＝1**。评分损失为：

```text
L_评分 = (0.1 + 0.2 + 0.1 - 1)² = 0.36
```

这个误差推动 Rubric 模型调整参数，让步骤分数总和更接近 1；答错时目标总和为 0。完整目标还包含限制模型偏移的 KL 项。

**此时没有教师告诉它“找到大学这一步应得多少分”，也没有教师指出哪条标准写错了。** 即使第一步被低估，只要其他步骤补足总分，也可能满足训练目标。例如 (0.2, 0.3, 0.5) 与 (0, 0, 1) 都能让总和等于 1。

这个例子说明：ARCO 后续直接优化的是奖励总和与结果的一致性；Rubric 文字通过共享参数间接变化，其质量需要另外检验。

## 数据集与实验

实验使用 HotpotQA、2WikiMultiHopQA、MuSiQue，每个数据集取 2,000 条训练样本和 500 条评估样本，骨干为 Qwen3-4B 与 Llama-3.2-3B。Agent 执行 Search 和 Finish，搜索范围限于每道题提供的上下文。

主结果中的 EM 如下，括号为相对该设置下最强基线的提升，单位为百分点：
HotpotQA：Qwen3-4B 42.80（+1.80），Llama-3.2-3B 36.40（+1.40）。
2WikiMultiHopQA：Qwen3-4B 65.20（+1.80），Llama-3.2-3B 59.60（+1.40）。
MuSiQue：Qwen3-4B 27.40（+0.80），Llama-3.2-3B 21.60（+2.80）。

ARCO 六组 EM 均最高，F1 在五组最高。消融中移除标准文字、改用固定标准或去掉轨迹前缀，六组 EM 均低于完整方法，支持这些设计在所测设置下有用。

论文按最佳开发集 EM 选择 checkpoint，主结果未报告多次运行的方差；这些结果不能直接外推为独立测试表现、统计显著优势或开放网络长程任务能力。

## 主要贡献

提出了将逐步标准生成、条件评分与 Agent 训练连接起来的过程奖励框架。预热提供标准和分数的学习起点，后续利用新轨迹的最终结果持续更新评价模型，并展示了多跳问答中的下游收益。

方法的关键限制也来自这个监督设计：最终结果只能约束步骤分数之和，无法唯一确定各步贡献；共享参数带来的标准变化缺少逐条正确性监督。因此，“参数持续更新”“任务成绩提高”“Rubric 本身更准确”需要分别验证。每步生成标准与双模型训练还会增加计算成本。
